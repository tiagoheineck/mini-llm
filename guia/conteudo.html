Apresentação

Modelos como o ChatGPT e o Claude são Large Language Models (LLMs): redes neurais treinadas para fazer uma única coisa, prever o próximo pedaço de texto. Neste roteiro você vai construir uma LLM do zero, com a mesma arquitetura delas (o Transformer decoder-only, a base do GPT), só que em miniatura: cerca de 0,8 milhão de parâmetros, treinada em poucos minutos na CPU do seu computador.

O modelo vai aprender a escrever no estilo de Dom Casmurro, de Machado de Assis, caractere por caractere. No caminho você vai mexer nos parâmetros de treino e ver, na prática, o efeito de cada um.

Objetivos de aprendizagem

Ao final deste roteiro, o estudante deverá ser capaz de:

  1. Explicar como uma LLM transforma texto em tokens e aprende a prever o próximo token.
  2. Identificar as peças de um Transformer: embeddings, atenção causal, MLP e conexões residuais.
  3. Treinar um modelo ajustando hiperparâmetros (learning rate, tamanho do modelo, contexto, dropout).
  4. Avaliar um modelo de linguagem com loss de validação e perplexidade.
  5. Diferenciar um modelo base de um modelo assistente (como o ChatGPT).

Tokenização

Texto vira uma sequência de números.

Transformer

A rede que olha o contexto e prevê o próximo token.

Treino

Ajustar os pesos para errar cada vez menos.

Avaliação

Medir o quanto o modelo generaliza para textos novos.

Passo 1 · Os dados

Toda LLM começa com texto. Vamos usar Dom Casmurro (domínio público, Projeto Gutenberg), com cerca de 380 mil caracteres:

{{cmd}}mkdir -p mini-llm/data && cd mini-llm curl -L https://raw.githubusercontent.com/tiagoheineck/mini-llm/main/data/input.txt -o data/input.txt{{/cmd}}

Pode trocar por qualquer arquivo .txt: letras de música, código-fonte, receitas, as conversas de um grupo. O modelo aprende o estilo do que você der para ele. Use pelo menos uns 200 KB de texto.

Tokenização

Redes neurais trabalham com números, não com letras. Tokenizar é converter o texto em uma sequência de inteiros. Aqui usamos a tokenização mais simples possível: cada caractere é um token.

{{cmd:python}}chars = sorted(set(texto)) # ['\n', ' ', '!', ..., 'a', 'b', ..., 'õ', 'ú'] → 95 caracteres stoi = {c: i for i, c in enumerate(chars)} encode("Capitu") # → [27, 50, 65, 58, 69, 70]{{/cmd}}

LLMs reais usam subpalavras (algoritmo BPE): "Capitu" viraria 2 ou 3 tokens, e o vocabulário tem ~100 mil tokens. A ideia é a mesma.

Passo 2 · O modelo

O arquivo model.py define o MiniGPT. O caminho de um texto por dentro dele é:

  1. Embeddings: cada token vira um vetor de n_embd números. Um segundo embedding codifica a posição do token na frase.
  2. Blocos Transformer (n_layer vezes), cada um com:
    • Atenção causal: cada token "consulta" os tokens anteriores para decidir o que é relevante. A máscara triangular impede que ele espie o futuro.
    • MLP: uma rede densa que processa cada posição.
    • LayerNorm e conexões residuais (x = x + ...), que estabilizam o treino de redes profundas.
  3. Cabeça de saída: transforma o vetor final em uma pontuação (logit) para cada token do vocabulário. Aplicando softmax, temos a probabilidade de cada caractere ser o próximo.
{{codigo:model.py|Arquitetura do MiniGPT (Transformer decoder-only)}}
Para entender a atenção

Cada token produz três vetores: Query ("o que estou procurando?"), Key ("o que eu ofereço?") e Value ("minha informação"). A atenção compara a Query de um token com as Keys dos anteriores (q @ k.T), transforma essas notas em pesos com softmax e faz uma média ponderada dos Values. Com n_head cabeças, isso acontece em paralelo, e cada cabeça pode aprender a prestar atenção em coisas diferentes.

Tabela 2 – Parâmetros são aprendidos; hiperparâmetros são escolhidos

Analogia

Pense em aprender a tocar violão. Os hiperparâmetros são o plano de estudo: quantas horas por dia, por quantas semanas, com qual método. Os parâmetros são o que muda no seu cérebro e nos seus dedos de tanto praticar. Você escolhe o plano; o aprendizado em si acontece sozinho.

Os dois estão ligados: alguns hiperparâmetros definem quantos parâmetros existem. Aumentar n_layer ou n_embd cria mais pesos na rede:

  • --n_layer 1 --n_embd 32 → cerca de 21 mil parâmetros;
  • o padrão (n_layer 4, n_embd 128) → cerca de 826 mil;
  • --n_layer 6 --n_embd 192 → cerca de 2,7 milhões.

Quando se diz que o GPT-3 tem "175 bilhões de parâmetros", são os pesos. Os hiperparâmetros dele cabem numa pequena tabela do artigo.

No código, a diferença aparece assim:

{{cmd:python}}# Parâmetros: o otimizador recebe os pesos e os ajusta a cada optimizer.step() optimizer = torch.optim.AdamW(model.parameters(), lr=cfg["learning_rate"]) # Hiperparâmetros: lidos uma vez do config.yaml e fixos durante o treino cfg["n_layer"], cfg["batch_size"], cfg["dropout"]{{/cmd}}

A exceção é o learning rate, que muda a cada passo. Mas ele muda segundo uma regra que você definiu (warmup + cosseno, explicada abaixo), então continua sendo um hiperparâmetro.

Tabela 3 – Efeito dos principais hiperparâmetros

O agendamento do learning rate

O learning rate não é constante. Nos primeiros warmup_iters passos ele sobe de zero até learning_rate (warmup), porque no início os pesos são aleatórios e passos grandes desestabilizam o modelo. Depois ele decai em cosseno até min_lr, para fazer ajustes finos no final. É o mesmo esquema usado no treino do GPT-3 e do LLaMA.

Passo 4 · O loop de treino

O train.py junta tudo. O coração dele são quatro linhas, repetidas max_iters vezes:

{{cmd:python}}xb, yb = get_batch("train") # 1. pega trechos aleatórios do texto _, loss = model(xb, yb) # 2. forward: prevê e mede o erro loss.backward() # 3. backward: calcula o gradiente de cada peso optimizer.step() # 4. ajusta os pesos na direção que reduz o erro{{/cmd}}

A loss é a entropia cruzada: o quão "surpreso" o modelo ficou com o caractere que realmente veio. Um modelo que chuta ao acaso entre 95 caracteres tem loss ln(95) ≈ 4,55. Tudo abaixo disso é aprendizado.

Tabela 4 – Evolução do texto gerado durante o treino

Treino × validação

Se a loss de treino continua caindo mas a de validação começa a subir, o modelo está decorando o texto em vez de aprender padrões: é o overfitting. O script avisa quando isso acontece.

Passo 6 · Gerando texto

Gerar texto é aplicar o modelo em laço: ele prevê a distribuição do próximo caractere, sorteamos um, colocamos no final do contexto e repetimos. Isso se chama geração autoregressiva.

{{codigo:generate.py|Geração de texto a partir do checkpoint}} {{cmd}}docker compose run --rm generate --prompt "Capitu" --temperature 0.8{{/cmd}}

Temperatura e top-k

  • Temperatura divide os logits antes do softmax. Abaixo de 1, as opções mais prováveis ficam ainda mais prováveis (texto previsível e repetitivo). Acima de 1, a distribuição fica mais achatada (texto criativo, depois caótico).
  • Top-k só deixa sortear entre os k caracteres mais prováveis, o que corta as escolhas absurdas.
Modelo base ≠ assistente

Experimente --prompt "Qual é a capital do Brasil?". O modelo não responde, apenas continua escrevendo como Machado de Assis. Ele é um modelo base: só sabe completar texto. O ChatGPT passa por etapas extras de treino com milhares de exemplos de perguntas e respostas (instruction tuning) e com avaliações humanas (RLHF) para aprender a se comportar como assistente.

Passo 7 · Avaliando o modelo (opcional)

A métrica clássica de modelos de linguagem é a perplexidade: exp(loss). Ela pode ser lida como "entre quantos caracteres o modelo está em dúvida, em média". Um chute aleatório tem perplexidade 95; nosso modelo chega a cerca de 6.

O script evaluate.py do repositório mede a perplexidade em textos que o modelo nunca viu. Copie-o junto com a pasta data/avaliacao e rode:

Atividades

Qualquer hiperparâmetro pode ser trocado na linha de comando, sem editar arquivos: docker compose run --rm train --learning_rate 1e-2. Para cada experimento, anote a loss de validação final e um trecho do texto gerado.

Exercício 1 · Learning rate

Treine com --learning_rate 1e-2 e depois com --learning_rate 1e-5. Compare as curvas de loss com o padrão (1e-3).

Ver resposta

Resposta: com 1e-5 a loss cai muito devagar e o modelo mal sai do chute aleatório em 2000 passos (passos pequenos demais). Com 1e-2 a loss tende a oscilar ou estagnar, porque os passos são grandes demais e "pulam" o mínimo. O learning rate é, em geral, o hiperparâmetro mais sensível.

Exercício 2 · Tamanho do modelo

Compare um modelo minúsculo (--n_layer 1 --n_embd 32 --n_head 2) com um maior (--n_layer 6 --n_embd 192 --n_head 6). Registre o número de parâmetros, o tempo de treino e a loss final.

Ver resposta

Resposta: o modelo minúsculo (~20 mil parâmetros) treina rápido, mas a loss estaciona alta e o texto não forma palavras. O maior (~2,7 milhões) atinge loss menor e escreve melhor, mas leva várias vezes mais tempo. Essa é a ideia das scaling laws: mais parâmetros, dados e computação geram modelos melhores, de forma previsível.

Exercício 3 · Janela de contexto

Treine com --block_size 8. O que acontece com a coerência do texto gerado? Por quê?

Ver resposta

Resposta: com só 8 caracteres de contexto, o modelo não consegue "lembrar" o início de uma palavra longa nem a palavra anterior. Ele ainda forma sílabas plausíveis, mas as palavras e frases perdem coerência. LLMs atuais têm contextos de centenas de milhares de tokens.

Exercício 4 · Provocando overfitting

Treine um modelo grande, sem dropout e por mais tempo: --dropout 0 --n_layer 8 --n_embd 256 --n_head 8 --max_iters 4000. Observe as duas losses. Em que momento a validação para de melhorar?

Ver resposta

Resposta: a loss de treino continua caindo, enquanto a de validação para de cair e começa a subir, e o script marca esses pontos. O modelo passou a decorar trechos de Dom Casmurro. Soluções: mais dados, dropout, modelo menor ou parar o treino mais cedo (early stopping).

Exercício 5 · Seu próprio corpus

Troque data/input.txt por outro texto (código Python, letras de música, um livro de outro autor) e treine de novo. Gere amostras e meça a perplexidade no texto original. O vocabulário mudou?

Ver resposta

Resposta: o modelo passa a imitar o estilo do novo corpus (com código, por exemplo, ele aprende indentação, def e parênteses). O vocabulário é montado a partir dos caracteres presentes no texto, então muda junto. Caracteres que não aparecem no treino ficam fora do vocabulário, e o modelo nem consegue representá-los.

Exercício 6 · Temperatura

Gere três textos com o mesmo prompt usando temperaturas 0,3, 1,0 e 1,8. Descreva a diferença e explique-a com base no softmax.

Ver resposta

Resposta: com 0,3 o texto fica repetitivo ("que a que a que…"), porque dividir os logits por um número pequeno amplia as diferenças e o caractere mais provável quase sempre vence. Com 1,8 a distribuição achata, caracteres improváveis passam a ser sorteados e o texto vira ruído. O valor 1,0 usa as probabilidades que o modelo realmente aprendeu.
